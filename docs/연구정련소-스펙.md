## 0. 핵심 개념

- **연구 정련소** = 단일 페이지. 사이드바 아이콘 🔬
- **세션(Session)** = 한 정련 시도 단위. `{vault[], 노드 트리, 분류, 정의서, 트리, 작업[]}` 한 묶음
- **버전(Version)** = 세션 스냅샷. v1, v2 … 보존 + diff
- **카테고리 4분**: ✅ 확정 / 🧪 가설 / 📋 백로그 / ❌ 폐기
- **저장 대상 3종**: 📖 프로젝트 위키(canon) / 📚 일반 문서(wiki) / 👤 개인 문서(personal)
- **자동/수동 경계**: LLM은 *추출·제안·문안*, 사람은 *결정·승인·수정*
- **SSoT 원칙**: 정련된 결과만 위키 canon. raw 원본은 vault 영구 보존, 편집 잠금

## 1. 6단계 흐름 (page workflow)

```
┌─ ⓪ Vault ──────┐ ┌─ ① 분해 ─────┐ ┌─ ② 분류 ─────┐
│ HTML/DOC/PDF   │→│ 단락·사상     │→│ 4분면 결정   │
│ 영구 보존(불변) │ │ → 노드 트리   │ │ (수동)       │
└───────────────┘ └──────────────┘ └──────────────┘
        ↓ 자동             ↓ 자동           ↓ 수동
        │
┌─ ⑤ WBS/태스크 ─┐ ┌─ ④ 정의서+트리┐ ┌─ ③ 결재 ─────┐
│ 1-클릭 생성    │←│ 자동 작성     │←│ 카테고리화   │
│ (선택+수정)    │ │ + 사람 편집   │ │ 묶음 결재    │
└───────────────┘ └──────────────┘ └──────────────┘
        ↓ 자동 제안 + 수동 승인
   기존 도구(WBS, 칸반, 이슈, 캘린더) 로 연결
```

## 2. 단계별 상세

### ⓪ Vault (원본 보존)
- 첨부 import (HTML/DOCX/PDF/MD) → `wiki_docs.kind='personal'` + `meta.vault=true` + `meta.refinerySessionId`
- prefix: `[VAULT] {원본 제목}`
- **편집 잠금** (UI에서 잠금 토글 막음)
- **작성자 강제** (§7) — `created_by` 미지정 시 import 차단
- 동일 세션에 vault N개 가능

### ① 분해 (Decompose) — 자동 + 진행 팝업
- LLM이 vault 본문 + htmlEmbeds 풀어 분석
- **분할 호출** (§6.2): 청크 분해 → 청크별 노드 추출 → 전역 dedup → 트리 합성
- 출력 노드:
  ```json
  {
    "id": "n_xxx", "title": "1~5단어",
    "summary": "1~2문장",
    "source_refs": [{"vault_doc_id": "...", "span_text": "...", "span_offset": 1234}],
    "ai_confidence": 0~100,
    "auto_category_hint": "canon|hyp|later|cut",
    "kind": "concept|hypothesis|risk|decision|fact|question",
    "parent_id": "n_yyy",
    "created_by": "auto:llm",  // 또는 user_id (사람이 직접 추가한 경우)
    "history": [{"action": "extracted", "at": "...", "by": "auto:llm", "model": "qwen2.5-coder:14b"}]
  }
  ```

### ② 분류 (Classify) — 수동
- 4분 버튼 + AI 추천 outline + 일괄 선택 + 메모
- 유사 노드 자동 그룹핑 (임베딩 유사도 0.85+) — MECE 위반 경고
- 분류 변경 시 `history[]`에 누가 언제 어떤 카테고리로 바꿨는지 push

### ③ 결재 (Approve)
- 분류 잠금 → 결재 묶음 자동 발행 (`review_requests`)
- 통과 → 분류 잠금 + 다음 단계 활성
- 1인 모드 옵션 (개인 프로젝트만)

### ④ 정의서+트리 자동 작성 (Compose) — §3, §4 상세
- LLM이 트리 + 각 파일 본문 자동 생성 (옵시디언 링크 적극 활용)
- **미리보기**에서 트리/파일명/본문 모두 직접 수정 가능
- **저장 대상 선택** (위키/일반/개인) — 노드 단위 분기
- **부분 commit** — 선택 항목만 적용

### ⑤ WBS/태스크/이슈 자동 제안
- 확정 노드 → 그룹핑 → WBS 제안 (3~7 노드를 1 WBS로)
- 가설 노드 → 이슈 (검증 인프라)
- 리스크 노드 → 이슈 (방어 항목)
- 각 항목 `[⊕ 생성]` 버튼 + 일괄 옵션

## 3. 저장 대상 분기 (★ v0.2 신규)

### 3.1 노드별 저장 대상 선택

분류 단계(②) 또는 정의서 단계(④)에서 노드마다 저장 대상 지정 가능:

| 저장 대상 | `wiki_docs.kind` | 용도 | 권한 |
|---|---|---|---|
| 📖 **프로젝트 위키** | `canon` | 팀 합의된 공식 시스템 정의 | 프로젝트 참여자 전원 읽기, 결재로 쓰기 |
| 📚 **일반 문서** | `wiki` | 작업용 메모·중간 산출물 | 팀 전원 읽기/쓰기 |
| 👤 **개인 문서** | `personal` | 개인 분석·실험 노트 | 본인 + visibility=public 시 팀 |

### 3.2 기본 매핑 (UI 추천, 변경 가능)

| 카테고리 | 기본 저장 대상 | 이유 |
|---|---|---|
| ✅ 확정 | 📖 프로젝트 위키 | 팀 합의 = canon |
| 🧪 가설 | 📖 프로젝트 위키 | 검증 추적 필요 |
| 📋 백로그 | 📚 일반 문서 | 비공식, 작업 메모 |
| ❌ 폐기 | 📖 프로젝트 위키 | 재제안 차단용 — 모두가 봐야 함 |
| (개별 노드) | 👤 개인 문서 | 사용자가 명시 선택 시 |

### 3.3 UI

정의서 미리보기에서 각 파일 우측에 드롭다운:
```
📁 0. 정체성/한줄정의.md  [📖 프로젝트 위키 ▼]  [편집] [삭제]
                            ↓ 클릭하면
                          ● 📖 프로젝트 위키 (canon)
                          ○ 📚 일반 문서

                          ○ 👤 내 개인 문서 (public)
                          ○ ❌ 생성 안 함
```

### 3.4 혼합 시나리오

한 세션에서:
- 합의 확정된 메커니즘 5개 → 📖 canon
- 내 개인 분석 노트 3개 → 👤 personal
- 팀 회의 메모 1개 → 📚 wiki

→ 한 번의 commit 으로 3개 대상에 분산 저장

### 4.2 옵시디언 스타일 링크 시스템 (★ v0.2 핵심)

#### 4.2.1 링크 문법 (이미 r210 안팎으로 지원)

| 문법 | 의미 |
|---|---|
| `[[파일명]]` | 같은 폴더·하위 폴더에서 첫 매칭 파일로 링크 |
| `[[폴더/파일명]]` | 절대 경로 |
| `[[파일#헤더]]` | 특정 헤더 anchor 로 점프 |
| `[[파일#헤더\|별칭]]` | 표시 텍스트만 별칭 |
| `[[#헤더]]` | 같은 파일 내 헤더 |
| `[^N]` | 각주 (vault 원본 점프) |

#### 4.2.2 자동 생성 정책

LLM이 본문 작성 시 다음 규칙 강제:
1. **다른 메커니즘 언급 시 무조건 `[[메커니즘파일명]]`** — 평문 X
2. **관련 가설/리스크 언급 시 `[[3.가설/DH-N_xxx]]`**
3. **vault 원문 인용 시 `[^N]`** (각주는 trailing reference 섹션에 모음)
4. **상위/하위 개념은 frontmatter 에 `tags`로**

#### 4.2.3 자동 백링크 패널

각 파일 페이지 하단에 "↩ 백링크 (N)" 자동 생성:
```markdown
---
## ↩ 백링크 (3)
- [[한장정의서]] — "3계층" 섹션에서 참조
- [[microloop_t0-t4]] — "관계" 섹션에서 참조
- [[DH-3_엔벨로프_은닉]] — "검증 대상" 섹션에서 참조
```

→ TDA Dashboard 가 이미 `[[]]` 링크 그래프를 추적하므로 자동 표시 가능.

## 6. LLM 사용 방식 + 진행 팝업 (★ v0.2 핵심)

### 6.1 단계별 LLM 호출 분할

각 단계는 큰 단일 호출 X → **작은 호출 N개로 분할**해 진행률 노출:

| 단계 | LLM 호출 수 | 분할 단위 | 모델 추천 | 사람 개입 시점 |
|---|---|---|---|---|
| ① 분해 | 청크 수만큼 (N개) + dedup 1회 + 트리 합성 1회 | vault 청크 4KB씩 | `qwen2.5-coder:14b` (속도 우선) | 없음 |
| ② 분류 추천 | 노드당 1회 (≤200 노드) | 노드 5개씩 묶음 → 40회 | `qwen2.5-coder:14b` | 매 노드 사람 결정 |
| ② 유사 노드 그룹핑 | 임베딩 1회 (전체) | 한 번 | `nomic-embed-text` | 그룹 채택 결정 |
| ④ 트리 합성 | 1회 (폴더·파일명 결정) | 확정 노드 메타만 | `qwen2.5-coder:14b` | 트리 편집 |
| ④ 파일 본문 | 파일당 1회 (≤30 파일) | 파일 단위 | `qwen2.5-coder:32b` (품질 우선) | 본문 편집 |
| ④ 옵시디언 링크 보강 | 1회 (트리 전체 후처리) | 확정된 파일명 목록 + 본문 | `qwen2.5-coder:14b` | 미리보기 후 적용 |
| ⑤ WBS 그룹핑 | 1회 | 확정 노드 메타 | `qwen2.5-coder:32b` (구조 추론) | 그룹·일정 편집 |
| ⑤ 태스크 분할 | WBS당 1회 | WBS 1개 | `qwen2.5-coder:14b` | 태스크 선택 |

### 6.2 분해 단계 분할 전략 (예시)

```
vault 본문 총 100KB → 청크 25개 (4KB씩)
  ↓
[1/27] 청크 1 분해... ━━━━━━━░░░░░░░░░░░ 7%   (qwen 14b · 노드 8개 추출)
[2/27] 청크 2 분해... ━━━━━━━━░░░░░░░░░░ 11%  (qwen 14b · 노드 11개)
...
[25/27] 청크 25 분해 ━━━━━━━━━━━━━━━━━━░ 92%
[26/27] 전역 dedup    ━━━━━━━━━━━━━━━━━░ 96%  (임베딩 유사도 0.85+ 묶음)
[27/27] 트리 합성     ━━━━━━━━━━━━━━━━━━ 100% (parent_id 결정)
```

→ 한 번에 100KB 통째로 보내면 컨텍스트 초과 + 메타 누출 위험. 청크별 작은 호출이 안전.

### 6.3 진행 위젯 (이미 인프라 있음)

기존 마인드맵 진행 위젯(`#mmp-prog-widget`) 패턴 재사용:
- 우측 하단 플로팅
- 최소화/닫기
- 단계별 진행률 바 (determinate / indeterminate)
- 로그 패널 (📜 진행 로그 N개)
- 단계 카운터 (N/M)
- 시간 경과 + ETA

신규 SSE 이벤트:
```python
yield {"event": "stage", "stage": "decompose", "step": 3, "total": 27, "message": "청크 3 분석 중..."}
yield {"event": "node_added", "node": {...}}  # 추출된 노드 1개 (스트리밍)
yield {"event": "progress", "current": 3, "total": 27, "percent": 11}
yield {"event": "chunk_done", "chunk_idx": 3, "nodes_extracted": 11}
yield {"event": "dedup_start"}
yield {"event": "dedup_done", "merged": 12, "kept": 87}
yield {"event": "tree_composed", "depth": 3, "nodes": 87}
yield {"event": "done", "summary": {...}}
```

### 6.4 프롬프트 전략

| 단계 | 시스템 프롬프트 핵심 | 사용자 메시지 |
|---|---|---|
| 분해 | "vault 청크 안 텍스트만 노드화. 메타 어구 금지(`<META_GUARD>`)" | `<<<VAULT_CHUNK i>>>...<<<END>>>` |
| 분류 추천 | "다음 노드 5개를 (확정/가설/백로그/폐기) 중 하나로 추천. 신뢰도 0-100. JSON only." | 노드 JSON 5개 |
| 트리 합성 | "확정 노드 N개를 §2.1 트리 템플릿 카테고리에 배치. JSON only." | 노드 메타 목록 |
| 파일 본문 | "노드 메타 + vault 발췌만 사용. 옵시디언 [[링크]] 강제. 각주 [^N]. JSON 한 개." | 노드 + 관련 노드 ID + vault 발췌 |
| 링크 보강 | "본문에서 다른 파일 언급 시 [[파일명]] 자동 치환. 단어 매칭만, 동의어 X." | 트리 파일 목록 + 본문 |
| WBS 제안 | "확정 노드 → 4~8시간 단위 WBS + 의존성. JSON." | 확정 노드 메타 |
| 태스크 분할 | "WBS 1개 → 4~8시간 태스크 N개. 4시간 미만이면 묶기, 8시간 초과면 분할." | WBS 1개 |

### 6.5 메타 누출 가드 (r215 재사용)

모든 본문 출력에 `_is_meta_leak` 필터:
- 키워드: MECE, 1레벨/2레벨, 노드 텍스트, 단문 길이, 출력 형식 등
- 누출 발견 시 노드 자동 제거 + warn 이벤트
- vault 본문 발췌도 누출 검사 (vault 원문에 진짜로 있는 단어인지 cross-check)

### 6.6 캐시 + 재시도

- vault 청크별 hash → 같은 청크 재분석 시 캐시 사용 (Sprint 1에선 옵션)
- LLM 호출 실패 시 3회 재시도 (exponential backoff 0.5s → 2s → 8s)
- 3회 실패 시 해당 청크/노드 skip + warn 표시 (전체 중단 X)

### 6.7 사용자가 LLM 호출 중 할 수 있는 것

- 진행 위젯 최소화 → 다른 작업 (위키 보기 등)
- "이 단계 건너뛰기" (e.g. WBS 제안 단계 skip → 수동 작성)
- "재실행" — 같은 vault 로 다시 분해 (모델 변경 등)
- "취소" — AbortController 로 진행 중인 LLM 호출 중단

### 7.6 작성자 누락 차단 (★ 견고화)

#### 프론트
- 모든 import/commit 액션 전에 `currentUser.id` 확인. 없으면 로그인 유도.
- import dialog: "작성자: {currentUser.name} ▼" — 변경 불가, 표시만

#### 백엔드
- 모든 신규/수정 endpoint:
  ```python
  if not req.user_id:
      raise HTTPException(422, "user_id is required (작성자 누락은 정책상 차단)")
  ```
- `wiki_docs` insert/update RLS policy:
  ```sql
  -- created_by 가 NULL 이면 거부
  create policy enforce_author on wiki_docs
    for all using (created_by is not null);
  ```

#### 마이그레이션 (기존 누락 데이터)
- 기존 `created_by IS NULL` 인 문서 발견 시:
  - UI 에서 노란 배지 "⚠ 작성자 불명 — 확인 필요"
  - 클릭 시 "이 문서 작성자 지정" 다이얼로그 → 가능한 후보 (마지막 수정자, 프로젝트 생성자) 제시
  - 일괄 마이그레이션 도구: 설정 > "작성자 누락 문서 정리"

### 7.7 보존 정책 (※ §13 미해결 → 해소안)

자동 생성 파일에 사람이 편집한 섹션이 다음 재생성 시 어떻게 보존되는가?

**채택안 — `<!-- USER:start --> ... <!-- USER:end -->` 마커**:
- 사람이 직접 추가한 섹션은 마커로 감싸도록 가이드
- LLM 재생성 시 마커 안 내용은 절대 건드리지 않음 (백엔드에서 추출 후 재삽입)
- 마커 없는 직접 편집은 archived_versions 에 보존, 재생성 시 사용자에게 "이전 편집 보존 안 됨" 경고

## 9. /goal 체크리스트 — 전체 진행 (★ v0.2 신규)

Claude `/goal` 으로 순차 실행 가능한 13단계. 각 단계는 "한 줄 명령" + "완료 조건" + "산출물".

```markdown
# 🎯 연구 정련소 — 한 세션 완주 체크리스트

## 준비
- [ ] **1. 세션 생성** — 사이드바 🔬 → [+ 새 정련 세션] → 제목 + 작성자 확인
- [ ] **2. vault import** — 첨부 N개 import. 각 파일 `created_by` 확인
- [ ] **3. 작성자 검증** — 세션 메타에 `participants[]` 자동 추가 확인

## 분해 (자동)
- [ ] **4. 분해 실행** — [① 분해 시작] 클릭. 진행 위젯 표시 (청크 1/N → N/N)
- [ ] **5. 노드 검토** — 추출된 노드 N개 트리 보기. 이상치 확인

## 분류 (수동, 가장 시간 많이 듦)
- [ ] **6. AI 추천 적용** — "추천대로 일괄 적용" 후 의심스러운 것만 재검토
- [ ] **7. 카테고리 확정** — 모든 노드가 ✅/🧪/📋/❌ 중 하나
- [ ] **8. 메모 입력** — 핵심 결정(특히 ❌)에 사유 메모

## 결재 (팀)
- [ ] **9. 결재 발행** — [분류 잠금] → 결재 자동 생성
- [ ] **10. 결재 통과 대기** — 팀 투표 (또는 1인 모드 즉시 통과)

## 정의서 + 트리
- [ ] **11. 트리 미리보기** — 자동 생성 트리 검토. 파일명·폴더명·본문 편집
- [ ] **12. 저장 대상 선택** — 각 파일 위키/일반/개인 분기. 부분 commit
- [ ] **13. 위키 적용** — [선택 적용] 또는 [전체 적용] 클릭

## 작업 생성
- [ ] **14. WBS 제안 검토** — 자동 그룹핑 확인. 분할/병합 편집
- [ ] **15. 태스크/이슈 일괄 생성** — [⊕ P0만] 또는 [⊕ 모두]

## 마감
- [ ] **16. 세션 archive** — status → published. 다음 vault 로 진행
```

### `/goal` 실행 예시

```
/goal 연구정련소 한세션 완주 — vault: cr3c.html, competitive.html

→ Claude:
[1/16] 세션 생성 중...
       세션 ID: rfs_xyz · 작성자: {currentUser} · 제목: "pB-4 코어 v1"
       ✓ 완료

[2/16] vault import 중...
       cr3c.html (84KB) imported. created_by: {currentUser}
       competitive.html (843KB) imported. created_by: {currentUser}
       ✓ 완료

[3/16] 작성자 검증...
       세션 participants[0] = {currentUser}
       ✓ 완료

[4/16] 분해 실행 중... [진행 위젯 표시]
       청크 1/27 분해 (qwen 14b, 노드 8개) ...
       ...
       청크 27/27 ✓
       전역 dedup: 99 → 87 노드
```

## 13. MVP 범위 (Sprint 1+2+3)

**MVP 핵심 가치 검증**: 한 세션으로 2 HTML 분해 → 분류 → 결재 → 정의서 미리보기 (편집 가능).

**보류** (Sprint 4+):
- 위키 commit (부분 선택)
- WBS 제안
- diff
- 1인/팀 모드 토글
- 옵시디언 백링크 자동
- `/goal` 통합

**MVP 성공 기준**:
1. 1600줄 + 843KB 2 HTML 로 노드 30+ 자동 추출 (메타 누출 0)
2. 5분 내 4분면 분류 완료 (AI 추천 활용)
3. 정의서 한 장 (1000자 이내, 옵시디언 링크 적용) + 모든 각주 vault 정확 점프
4. **작성자 NULL 인 산출물 0** (백엔드 422 검증)
5. 진행 위젯에 모든 LLM 호출 단계 노출
