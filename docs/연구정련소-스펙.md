# 🔬 연구 정련소 (Research Refinery) — 상세 스펙 v0.1

> raw 연구 문서를 받아 **정련(분해 → 분류 → 합의 → 정의서 → 위키 트리 → WBS/태스크)** 까지 한 페이지에서
> 완결시키는 페이지. r170~r222 까지 만든 모든 인프라(마인드맵 explain · RAG 인덱싱 · 결재 · WBS ·
> 임베디드 검색)가 자연스럽게 만나는 종착역.

문서 작성일: 2026-06-04 · 대상 리비전: r223+ · 상태: 설계 가설 (구현 미시작)

## 0. 핵심 개념

- **연구 정련소** = 단일 페이지. 사이드바 아이콘 🔬
- **세션(Session)** = 한 정련 시도 단위. `{vault[], 노드 트리, 분류 결정, 정의서, 생성된 WBS/태스크}` 한 묶음
- **버전(Version)** = 세션의 스냅샷. v1, v2 … 보존 + diff
- **카테고리 4분**: ✅ 확정 / 🧪 가설 / 📋 백로그 / ❌ 폐기
- **자동/수동 경계**: LLM은 *추출·제안*, 사람은 *결정·승인*
- **단일 진실(SSoT)**: 정련된 결과만이 `project canon` 위키에 들어감. raw 원본은 vault 에 보존

## 1. 6단계 흐름 (page workflow)

```
┌─ ⓪ Vault ────────┐ ┌─ ① 분해 ─────┐ ┌─ ② 분류 ─────┐
│ raw HTML/DOC/PDF │→│ 단락·사상     │→│ 4분면 결정   │
│ 영구 보존(불변)   │ │ → 노드 트리   │ │ (수동)       │
└─────────────────┘ └──────────────┘ └──────────────┘
        ↓                ↓ 자동           ↓ 수동
        │
┌─ ⑤ WBS/태스크 ───┐ ┌─ ④ 정의서 ───┐ ┌─ ③ 결재 ─────┐
│ 1-클릭 프로젝트  │←│ 한 장 + 트리  │←│ 카테고리화   │
│ 생성             │ │ 자동 작성     │ │ 묶음 결재    │
└─────────────────┘ └──────────────┘ └──────────────┘
        ↓ 자동 제안 + 수동 승인
   기존 도구 시스템(WBS, 칸반, 이슈, 캘린더) 으로 흘러감
```

각 단계별 자세히:

### ⓪ Vault (원본 보존)
- 사용자가 HTML/DOCX/PDF/MD 첨부 → 즉시 `wiki_docs.kind='personal'` + `meta.vault=true` + `meta.refinerySessionId` 로 저장
- prefix: `[VAULT] {원본 제목}`
- **편집 잠금** (UI 에서 잠금 토글 막음)
- 같은 세션의 vault 가 N 개 가능 (관련 정합 문서 함께 분석)

### ① 분해 (Decompose) — 자동
- LLM 이 vault 의 모든 본문 + htmlEmbeds 풀어 한 번에 분석
- 출력: 노드 트리 (central → 카테고리(§)→ 노드 → 자식)
- 각 노드는:
  - `title` (1~5 단어)
  - `summary` (1~2 문장)
  - `source_refs[]` = [{vault_doc_id, span_text, span_offset}]  ← **각주 원천**
  - `ai_confidence` (0~100)
  - `auto_category_hint` (✅/🧪/📋/❌ 추천)
  - `kind` (concept / hypothesis / risk / decision / fact / question)

기술 — r196 마인드맵 생성기 재사용 + 출력 스키마 확장.

### ② 분류 (Classify) — 수동
- 노드 목록 view (테이블 + 그리드 + 트리 토글)
- 각 노드 우측에 4 버튼: `[✅ 확정] [🧪 가설] [📋 백로그] [❌ 폐기]`
- AI 추천 카테고리는 점선 outline 로 미리 표시 — 클릭 시 확정
- **일괄 작업**: Shift+클릭 다중 선택 → 일괄 카테고리 적용
- 필터: 신뢰도 점수 / kind / 미분류만 / 추천 카테고리별
- **MECE 경고**: 유사 노드(임베딩 유사도 0.85+) 자동 그룹핑, "이 중 하나만 채택?" 제안
- 노드별 메모 입력 (왜 채택/거절?)

### ③ 결재 (Approve) — 팀 합의
- "분류 잠금" 버튼 → 결재 묶음 자동 발행
  - `review_requests.title` = `[정련소] {세션명} 분류 v{n} 결재`
  - `target_doc_id` = 세션 id
  - `metadata.refinery_classifications[]` = 모든 노드의 분류 결정
- 결재 통과 → 분류 잠금 (한 sprint 동안 변경 불가, G7 hygiene)
- 1 인 모드 옵션: "솔로 프로토타이핑 — 결재 없이 진행" (개인 프로젝트 전용)

### ④ 정의서 + 위키 트리 자동 작성 (Compose)
- 확정 통과 후 LLM 이 위키 디렉토리 트리 + 각 파일 본문 자동 생성
- 모든 인용은 `[^N]` 각주 — 클릭 시 vault 원본의 정확한 span 으로 점프 + 강조
- 상세 트리 구조는 §2 참조
- 사용자가 "트리 미리보기 + 수정" 후 "위키에 적용" 클릭 시 일괄 `wiki_docs` insert

### ⑤ WBS/태스크/이슈 자동 제안 (Decompose to Work)
- 확정 노드 → 그룹핑 → WBS 노드 제안
  - 노드 3~7 개를 묶어 1 WBS (1:1 매핑 금지)
  - LLM 이 의존성·timeline 추정
- 각 WBS 에서 4~8 시간 단위 태스크 N 개 자동 분할
- 가설 노드 → 이슈 (검증 인프라 항목)
- 리스크 노드 → 이슈 (방어 항목)
- **버튼**: `[⊕ 모두 생성]` `[⊕ 우선순위 P0 만]` `[개별 선택 후 생성]`

## 3. 위키 적용 (commit) 동작

### 3.1 일괄 트리 적용

1. 사용자가 정의서 미리보기 화면에서 `[위키에 적용]` 클릭
2. confirm dialog — "**총 N 개 파일·M 개 폴더가 위키에 생성됩니다. 기존 동일 경로 파일은 새 버전으로 덮어쓰기 (이전 버전은 보관). 진행할까요?**"
3. 백엔드:
   - 같은 경로에 기존 파일 있으면:
     - 새 버전 파일 생성
     - 기존을 `wiki_docs.meta.archived_versions[]` 에 push (raw content 보존)
     - 새 본문에 changelog footer 추가
   - 폴더는 `wiki_docs.kind='wiki'` + `meta.isFolder=true`
   - 모든 신규 doc 에 `meta.refinerySessionId`, `meta.refineryNodeIds[]` 기록
4. 응답 후 좌측 위키 트리 자동 새로고침

### 3.2 각주 → vault 원본 점프

- 각주 hyperlink format: `#vault-doc:{doc_id}?find={url_encoded_span}`
- 클릭 핸들러 (이미 r221 에 있음): `_mmpExGoToSource` 재사용
- vault 문서가 HTML 임베드면 r221 의 `tda-embed-find` postMessage 로 iframe 내부 검색·강조

### 3.3 부분 적용 (옵션)

- 카테고리 단위 적용 (확정만, 가설만)
- 파일 단위 적용 (선택 파일만 commit)
- 미리보기에서 체크박스로 선택

## 4. DB 스키마

### 4.1 신규 테이블 — `refinery_sessions`

```sql
create table if not exists refinery_sessions (
  id text primary key,                     -- 'rfs_xxx'
  project_id text,
  title text,                              -- '연구 정련 — pB-4 코어 (2026-06-04)'
  created_by text,
  created_at timestamptz default now(),
  updated_at timestamptz default now(),
  status text default 'draft',             -- draft | classified | approved | published | archived
  vault_doc_ids jsonb default '[]',        -- ['vault_xxx', ...]
  nodes jsonb default '[]',                -- 분해 결과 노드 트리
  classifications jsonb default '{}',      -- { node_id: 'canon'|'hyp'|'later'|'cut', memo, decided_by, decided_at }
  review_request_id text,                  -- 결재 발행 시
  generated_tree jsonb,                    -- 위키 트리 미리보기 (commit 전)
  generated_canon_doc_ids jsonb default '[]',  -- commit 후 생성된 wiki_docs id
  generated_wbs_ids jsonb default '[]',
  generated_task_ids jsonb default '[]',
  generated_issue_ids jsonb default '[]',
  parent_session_id text,                  -- 버전: v2 라면 v1 의 id
  version_label text                       -- 'v1', 'v1.1' 등
);
```

### 4.2 기존 테이블 확장 (`wiki_docs.meta` 키 추가)

| meta 키 | 의미 |
|---|---|
| `vault: true` | vault 원본 (편집 잠금) |
| `refinerySessionId` | 어느 정련 세션에서 만들어졌는지 |
| `refineryNodeIds[]` | 어느 노드에서 파생됐는지 |
| `archived_versions[]` | 위키 적용 시 덮어쓰기 전 보관 |
| `category` | 'canon'|'hyp'|'later'|'cut' (위키 트리 폴더 자동 라벨) |
| `playtest_status` | 가설 파일 전용: 'pending'|'positive'|'negative' |

### 4.3 마이그레이션 SQL

- 기존 패턴(DB_OPTIONAL_TABLES) 사용
- 사용자 설정 → DB 스키마 점검 → 1 클릭 적용
- `refinery_sessions` 만 신규 테이블, 나머지는 `meta` jsonb 안 → 마이그레이션 무

- `stage` / `progress` / `node` (each node streamed) / `done`

### 5.2 `/refinery/compose-tree` (POST · SSE)
입력: `session_id`, 확정된 카테고리화 + node 목록
출력: 위키 트리 (folders + files with content) JSON
- 미리보기 only — DB 변경 X

### 5.3 `/refinery/apply-tree` (POST)
입력: `session_id`, `tree` (또는 부분 선택)
동작: wiki_docs 일괄 insert + archived_versions 처리
응답: `{ created: [...ids], archived: [...ids] }`

### 5.4 `/refinery/propose-work` (POST · SSE)
입력: `session_id` (확정 노드만)
출력: WBS 트리 + 태스크 + 이슈 제안 JSON

### 5.5 `/refinery/apply-work` (POST)
입력: 선택된 WBS/태스크/이슈
동작: `wbs_nodes`, `tasks`, `issues` 일괄 insert

### 5.6 `/refinery/diff` (POST)
입력: `session_id_a`, `session_id_b` (보통 v1, v2)
출력: 추가/변경/삭제된 노드 + 카테고리 변경 + 새 위키 파일

### 5.7 LLM 프롬프트 격리 (r215 패턴)

- 모든 LLM 호출에 시스템 메시지 = "출력은 JSON 한 개. vault 원문에 등장하는 표현만 사용. 메타 어구 금지."
- vault 본문은 `<<<VAULT>>> ... <<<END_VAULT>>>` 명시적 구분자로 감쌈
- 출력 후 `_is_meta_leak` 필터 적용

## 7. 구현 절차 (Sprint 단위)

### Sprint 1 — 인프라 + ⓪ Vault + ① 분해

- ① 분해: SSE 진행률 + 노드 트리 시각화
- 검증: 사용자 첨부 두 HTML 로 노드 50+ 추출 확인

### Sprint 2 — ② 분류
- 노드 카드 UI · 4분 버튼 · AI 추천 outline · 일괄 선택

- MECE 그룹 제안 (임베딩 유사도 기반)
- 메모 입력

### Sprint 3 — ③ 결재 + ④ 정의서 미리보기
- 결재 묶음 자동 발행 + 통과 → 잠금

### Sprint 4 — ④ 위키 적용 + ⑤ 작업 제안
- `/refinery/apply-tree` — 일괄 insert + archived_versions
- 위키 트리 자동 새로고침
- `/refinery/propose-work` — WBS/태스크/이슈 제안

- 검증: 정련 → 위키 적용 → WBS 5 개 + 태스크 20 개 자동 생성, 모든 항목이 정련 세션과 양방향 링크

### Sprint 5 — 버전 + diff + playtest 승격
- `/refinery/diff` — v1 vs v2 비교 UI

- 검증: 팀원 A 가 v1.7 가져온다고 가정 → 새 vault → 새 세션 → diff 정확

## 9. MVP 범위 (Sprint 1+2+3 까지)

**핵심 가치 검증**: 한 세션으로 두 HTML 분해 → 분류 → 결재 → 정의서 미리보기.
**보류**: 위키 commit, WBS 제안, diff, 1 인/팀 모드 토글 (모두 Sprint 4+).
**MVP 성공 기준**:
1. 1600 줄 + 843KB 두 HTML 로 노드 30+ 자동 추출
2. 5 분 내 4분면 분류 완료
3. 정의서 한 장 (1000 자 이내) + 각주 모두 vault 정확 점프
4. 메타 어구 누출 0
